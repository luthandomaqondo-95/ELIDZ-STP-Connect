# Postal codes (South Africa) — Free setup

Goal: **accurate postal codes without paid APIs** and **without manual entry**.

We do this by importing the GeoNames ZA postal-code dump into Supabase and querying it from the mobile app.

## 1) Create the table + RPC in Supabase

Run the SQL in:

- `mobile/database/create_za_postal_codes.sql`

This creates:
- `public.za_postal_codes`
- RPC `public.search_za_postal_codes(p_query text, p_limit int)`
- A public read policy (safe: contains no user data)

## 2) Download GeoNames ZA dump

1. Download: `https://download.geonames.org/export/zip/ZA.zip`
2. Unzip it and locate `ZA.txt`

The dump is **tab-delimited** and documented here:
- `https://download.geonames.org/export/zip/readme.txt`

## 3) Convert `ZA.txt` to CSV

Do this **after** you have downloaded and unzipped `ZA.zip` so that `ZA.txt` exists somewhere on your computer.

### Option A: ZA.txt is inside your project folder

1. Open a terminal (PowerShell or Command Prompt).
2. Go to your project root (where the `mobile` folder is):
   ```bash
   cd C:\Users\tebog\OneDrive\Documents\Projects\ELIDZ-STP-Connect
   ```
3. If `ZA.txt` is in that folder, run:
   ```bash
   node mobile/scripts/geonames_za_to_csv.mjs --input ZA.txt --output za_postal_codes.csv
   ```
4. The file `za_postal_codes.csv` will be created in that same folder.

### Option B: ZA.txt is somewhere else (e.g. Downloads)

1. Open a terminal.
2. Go to your project root:
   ```bash
   cd C:\Users\tebog\OneDrive\Documents\Projects\ELIDZ-STP-Connect
   ```
3. Run the script with **full paths** to your `ZA.txt` and where you want the CSV:
   ```bash
   node mobile/scripts/geonames_za_to_csv.mjs --input "C:\Users\tebog\Downloads\ZA.txt" --output "C:\Users\tebog\OneDrive\Documents\Projects\ELIDZ-STP-Connect\za_postal_codes.csv"
   ```
   (Replace `C:\Users\tebog\Downloads\ZA.txt` with the actual path to your `ZA.txt`.)

### Check the result

Open `za_postal_codes.csv` in a **text editor** (e.g. Notepad, VS Code), **not Excel**. The first line must look exactly like this (comma-separated):

```text
country_code,postal_code,place_name,admin_name1,admin_name2,admin_name3,latitude,longitude,accuracy
ZA,0002,Pretoria,...
```

If you see the first line looking like `ZA 0002 Pretoria ...` (no commas), you are **not importing the correct file**.

## 4) Import CSV into Supabase

Use Supabase Dashboard:

- **Important (RLS)**: before importing, temporarily disable RLS (bulk import is an insert).
  - Run: `mobile/database/za_postal_codes_import_helper.sql`
  - After import, re-enable:
    - `alter table public.za_postal_codes enable row level security;`

- Table Editor → `za_postal_codes` → **Import data**
- Upload **`za_postal_codes.csv`** (generated by the script) — **do not upload `ZA.txt`**
- Make sure **"File has header row"** (or similar checkbox) is enabled
- Ensure the column mapping matches:
  - `country_code`
  - `postal_code`
  - `place_name`
  - `admin_name1`
  - `admin_name2`
  - `admin_name3`
  - `latitude`
  - `longitude`
  - `accuracy`

Do **not** try to import values for:
- `id` (auto identity)
- `created_at` (default `now()`)

## 5) App behavior

The signup screen queries postal codes using:

- `supabase.rpc('search_za_postal_codes', { p_query: <city>, p_limit: <n> })`

Postal code selection is enforced via a Picker (no free-text entry) for all cities except the special `"Other"` option.
